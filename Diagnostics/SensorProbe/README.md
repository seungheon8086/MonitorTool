# SensorProbe: 온도·팬·전력 센서 읽기 진단

[설계 문서](../../docs/PROJECT_DESIGN.md) 7장 5번 항목(온도·팬을 읽기만 하는 진단)을 확인합니다. 값을 바꾸는 명령은 보내지 않습니다.

## 확인할 것

1. 관리자 권한 없이 SMC 키와 HID 온도 센서를 읽을 수 있는지, 어떤 키·센서가 있고 형식(단위)은 무엇인지
2. 어느 온도 센서가 E코어·P코어·GPU·ANE 부하에 반응하는지 (대표 온도 'CPU 최고'·'GPU 최고'에 쓸 센서 고르기)
3. 팬 개수, 실제 RPM, 최소·최대·목표 RPM, 모드 키, 그리고 0 RPM과 읽기 실패의 구분
4. SMC 전력 키(P…) 중 powermetrics의 CPU 전력과 같이 움직이는 키가 있는지 (관리자 권한 없이 CPU 전력을 읽을 다른 길)
5. ANE 드라이버(IORegistry) 속성 중 ANE 사용률로 쓸 만한 값이 있는지 (가만히일 때와 ANE 부하 중 비교)

## 구성

- `sensor_probe.swift`: 관리자 권한 없이 SMC(AppleSMC의 읽기 명령만 사용)와 HID 온도 센서(IOHIDEventSystemClient)를 읽는 진단 도구. `list`(전체 목록), `sample`(T·F·P 키와 HID 온도를 1초마다 기록), `ane-ioreg`(ANE 관련 IORegistry 속성 저장). SMC 구조체 배치는 [Stats](https://github.com/exelban/stats)(MIT)의 방식을 참고
- `cpu_burn.swift`: 계산 부하 도구. QoS가 background인 스레드는 E코어에서만 돌고, userInteractive 스레드는 P코어를 먼저 써요
- `../PowerProbe/ane_load.swift`: GPU·ANE 부하에 다시 써요
- `measure.sh`: 아래 순서로 기록해요. 단계마다 powermetrics(관리자 권한)도 함께 기록해서 비교해요
- `results/`: 결과 원본

| 단계 | 부하 | 시간 |
|---|---|---|
| A | 없음 | 20초 |
| B | E코어 (background 스레드 4개) | 25초 |
| C | P코어 (userInteractive 스레드 8개) | 25초 |
| C2 | 식히기 | 15초 |
| D | GPU (Vision 이미지 분류) | 25초 |
| D2 | 식히기 | 15초 |
| E | ANE (Vision 이미지 분류). 시작할 때 ANE IORegistry 속성 저장 | 25초 |
| F | 식히기 | 20초 |

## 실행

터미널에서 실행합니다. 앞에 `sudo`를 붙이지 않습니다. 관리자 암호는 비교용 powermetrics에만 쓰여요. 5분쯤 걸리고, 측정 중에는 다른 무거운 작업을 피해 주세요.

```sh
bash ~/Desktop/MonitorTool/MonitorTool/Diagnostics/SensorProbe/measure.sh
```

## 결과 기록

- 검증 기기: MacBookPro18,1 (M1 Pro), macOS 27.0.1
- 2026-10-23 측정. 원본은 `results/`에 있고, 표본은 `sample-*.tsv.gz`, SMC 키 전체는 `smc-keys.tsv.gz`예요.
- 측정 조건: 다른 프로그램이 돌고 있어서 가만히 단계도 CPU 3.7 W, P0 묶음 활성 57%였어요. 열 압력은 내내 Nominal이었어요.
- 부하는 의도대로 걸렸어요(powermetrics 기준). E코어 단계는 E 묶음 100%, P코어 단계는 모든 묶음 97~100%에 CPU 11.1 W, GPU 단계는 GPU 활성 97%에 7.6 W, ANE 단계는 ANE 1.2 W였어요.

**1) 관리자 권한 없이 읽기**

- SMC 키 2,179개를 일반 사용자(uid 501)로 읽었어요. 온도 후보(T…) 211개, 팬(F…) 25개, 전력 후보(P…) 68개예요. 173개 키는 읽기 오류가 났지만 T·F·P 키는 모두 읽혔어요.
- HID 온도 센서는 64개였지만 같은 이름이 여러 번 나와요(`gas gauge battery` 6번, `PMU tdie1`·`tdie2` 4번 등). `als-temp`는 값을 주지 않았어요.

**2) 온도 센서의 부하별 반응** (단계 평균, °C)

| 묶음 | 가만히 | E코어 | P코어 | 식힘 | GPU | 식힘 | ANE |
|---|---|---|---|---|---|---|---|
| P코어 `Tp01·05·0D·0H·0L·0P·0X·0b` | 54.2 | 54.2 | **63.1** | 56.6 | 59.5 | 57.8 | 58.9 |
| E코어 `Tp09·0T` | 54.0 | 54.4 | **60.7** | 56.8 | 59.4 | 58.2 | 58.9 |
| GPU `Tg05·0D` | 50.4 | 53.1 | 57.0 | 56.5 | **63.6** | 58.4 | 58.2 |
| `TC10~13` | 47.6 | 47.4 | **58.0** | 48.9 | 53.2 | 50.6 | 52.4 |
| `TC20~23` | 45.8 | 46.3 | 50.7 | 49.3 | **58.3** | 51.3 | 51.6 |
| ANE `Ta00·01·02·04` | 0 | 0 | 0 | 0 | 0 | 0 | **51.4** |
| HID `PMU tdie0~10` | 41.2 | 41.7 | 42.4 | 43.0 | 43.7 | 44.3 | 44.7 |

- **P코어 센서:** Stats가 M1 계열의 P코어로 쓰는 키 8개가 P코어 부하에서 가장 크게(약 +9 °C) 올랐어요.
- **E코어 센서:** Stats가 E코어로 쓰는 `Tp09`·`Tp0T`는 E코어 부하에서 +0.4 °C에 그쳤어요. E코어 2개는 다 써도 1 W 남짓이고, 가만히 단계에도 다른 프로그램의 부하가 있어서 E코어만의 반응은 분명하지 않았어요. CPU 부하에는 확실히 반응해서 CPU 영역 센서로는 쓸 수 있어요.
- **GPU 센서:** `Tg05`·`Tg0D`는 GPU 부하에서 가장 높았어요(최고 65 °C). CPU 부하에도 오르는데, 같은 칩 안이라 열이 퍼지기 때문으로 보여요. `TC20~23`도 GPU 부하에 가장 크게 반응했어요(Stats 목록에는 없는 키).
- **ANE 센서:** `Ta00~Ta06`은 ANE가 꺼져 있으면 0(`Ta00·01·02·04`)이거나 멈춘 값(`Ta05` 8.5, `Ta06` 10.9)이고, ANE 부하 중에만 49~62 °C를 보였어요. 다른 부하에는 반응하지 않았어요.
- **0인 값:** `Tg04`·`Tg0C`도 가끔 0이 나왔어요(170번 중 3번). 이런 0은 0 °C가 아니라 '센서 꺼짐'으로 다뤄야 해요. `TH1a`·`TH1b`·`TVMD`·`Tz11~18`·`Tz1j`는 항상 0이라 센서가 없는 키로 봐요.
- **짝 키:** `Tp00`과 `Tp01`처럼 이름이 이웃한 키는 변화량이 똑같고 값만 약 9 °C 달라요. 같은 센서를 다르게 보정한 값으로 보이며, Stats처럼 높은 쪽을 써요. 가만히일 때 62 °C 안팎인 `Tp02·06·0A·0E·0I·0M·0Q·0U·0Y·0c`는 무엇을 재는지 확인하지 못해서 대표 온도에서 빼요.
- **HID PMU 센서**(`tdie`·`tdev`·`TP`): 부하와 상관없이 41 → 45 °C로 천천히만 올랐어요. 전원 관리 칩 쪽 온도로 보여서 CPU·GPU 대표 온도로 쓰지 않아요.
- **배터리·SSD:** SMC `TB0T`·`TB1T`·`TB2T`와 HID `gas gauge battery`는 32 °C 안팎, HID `NAND CH0 temp`는 34~36 °C였어요.

**3) 팬**

| 키 | 팬 1 (`F0…`) | 팬 2 (`F1…`) |
|---|---|---|
| 실제 RPM (`Ac`) | 0 | 0 |
| 최소 RPM (`Mn`) | 1,499 | 1,499 |
| 최대 RPM (`Mx`) | 4,296 | 4,744 |
| 목표 RPM (`Tg`) | 0 | 0 |
| 모드 (`Md`) | 3 | 3 |

- 팬 개수(`FNum`)는 2개예요. 측정 내내 두 팬 모두 0 RPM이었고 `FOff`는 1이었어요. 읽기는 모두 성공했으니 이 0은 '읽기 실패'가 아니라 '팬 정지'예요.
- 부하가 짧아 칩 온도가 66 °C 안팎에 그쳤고, 팬이 돌지 않았어요. 팬이 도는 동안의 RPM은 실사용 점검에서 확인해요.

**4) SMC 전력 키**

CPU 전력만 따로 따라가는 키는 없었어요. `PSTR`은 시스템 전체 전력으로 보이고(가만히 15 W → CPU·GPU 부하 25~27 W), `PZC0`·`PHPS`·`PSVC` 등은 CPU와 GPU를 합친 부하를 따라가요(powermetrics CPU·GPU 전력과의 상관 0.5~0.7). 관리자 권한 없이 CPU·ANE 전력을 읽을 길은 SMC에도 없었어요.

**5) ANE 드라이버 (IORegistry)**

ANE 관련 항목은 3개(`H11ANEIn`, `H1xANELoadBalancer`, `ANEClientHints`)였어요. ANE 부하 중에 바뀐 값은 전원 상태(`IOPowerManagement.CurrentPowerState` 0 → 1)뿐이고, 사용률이나 사용 시간을 세는 값은 없었어요. ANE 코어 수는 16개(`h13g`)로 나와요.

판정:

- 온도·팬은 관리자 권한 없이 SMC로 읽는다. HID 센서는 대표 온도에 쓰지 않는다.
- CPU 최고 = `Tp01·05·09·0D·0H·0L·0P·0T·0X·0b` 중 최고값, GPU 최고 = `Tg05`·`Tg0D` 중 최고값. 센서가 0을 주면 0 °C가 아니라 '센서 꺼짐'으로 다룬다.
- 팬은 2개이고, 0 RPM은 '정지'로 표시한다. 회전 중 값은 실사용 점검에서 확인한다.
- CPU·ANE 전력은 SMC로도 대신할 수 없어 관리자 권한 보조 프로그램이 필요하다.
- ANE 사용률을 재는 값은 IORegistry에도 없다(측정 불가 결론 유지).


## 추가 확인: GPU 온도 9.2 °C (2026-10-30, macOS 27.2 26B123)

팬 진단(FanProbe) 중 가만히일 때 'GPU 최고'(`Tg05`·`Tg0D`)가 9.2 °C로 자주 떨어지는 것을 보고 원인을 찾았어요. `check_gpu_offset.sh`(관리자 권한 없이 60초 기록, 결과 `results-272/`).

- `Tg05 = Tg04 + 9.2`, `Tg0D = Tg0C + 9.2`: 10-23(27.0.1) 170개, 10-30(27.2) 60개 표본 모두 차이가 정확히 9.200이에요. `Tg05`·`Tg0D`는 독립 센서가 아니라 원래 센서에 고정 보정을 더한 키예요.
- 9.2 °C가 나온 때는 모두 원래 센서 `Tg04`·`Tg0C`가 0(꺼짐)이었어요(0 + 9.2). 두 센서는 늘 함께 꺼지고 켜졌어요. GPU 전력이 0~4 mW일 때예요.
- 27.0.1에서는 170개 중 3개였는데, 27.2에서는 가만히 60초 중 26초(43%)였어요. 꺼짐은 1~3초가 대부분이고 가장 길게 7초 이어졌어요. 켜져 있을 때 GPU 최고는 48.8~51.2 °C였어요.
- CPU 키도 같은 구조예요: `Tp05 = Tp04 + 8.98`, `Tp09 = Tp08 + 8.98`, `Tp0H = Tp0G + 9.10`, `Tp0L = Tp0K + 8.84`, `Tp0P = Tp0O + 8.90`, `Tp0X = Tp0W + 8.93`(`Th01 = Th00 + 7.33`도). CPU 쪽 원래 센서는 0이 된 적이 없어요.

**결정 (사용자, 2026-10-30)**: 'GPU 최고'는 보정 키를 그대로 쓰되, 짝인 원래 센서가 0이면 그 보정 키는 꺼진 것으로 봐요. 두 GPU 센서가 모두 꺼지면 10초까지는 직전 값을 보여주고(그래프·위젯 기록에는 새 점을 찍지 않음), 그보다 길면 '꺼짐'이에요. 팬 안전장치(보조 프로그램)도 같은 규칙을 써요.
