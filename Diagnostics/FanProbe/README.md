# FanProbe: 팬 제어 가능 여부 진단

8단계 선택 기능 '팬 RPM 조절(패널 전용)'을 만들기 전에, 이 Mac(MacBookPro18,1 · M1 Pro, macOS 27.2)에서 보조 프로그램이 SMC로 팬을 제어할 수 있는지 확인합니다. SensorProbe는 읽기만 했고, 이 진단은 처음으로 SMC 쓰기(명령 6)를 씁니다.

## 확인할 것

1. 팬 관련 키(`F…`)의 형식·크기·속성 바이트. 시험 모드 키 `Ftst`(M3·M4에서 수동 모드를 풀 때 쓰는 키), M5식 모드 키 `F0md`, 옛 Intel 키 `FS! `가 있는지
2. 관리자 권한 없이 쓰면 거절되는지, 거절될 때 어떤 오류인지 (지금 값을 그대로 다시 써서 값은 바뀌지 않음)
3. 관리자 권한으로 `F{i}Md = 1`(수동)이 바로 받아들여지는지 (M1은 `Ftst` 없이 된다고 알려져 있음)
4. 수동 모드에서 `F{i}Tg`(목표 RPM)를 쓰면 `F{i}Ac`(실제 RPM)가 따라가는지, 얼마나 빨리 따라가는지, 시스템(thermalmonitord)이 모드를 3으로 도로 가져가는지
5. `F{i}Md = 0`을 쓰면 시스템 제어로 돌아가는지(모드 값이 0으로 남는지 3으로 바뀌는지, 팬이 다시 멈추는지)

잠자기·깨어남 뒤 수동 모드 유지 여부, 보조 프로그램이 끝날 때 복원은 앱에 넣을 때 따로 확인합니다.

## 안전장치

- 목표 RPM은 팬의 최소~최대 안으로만 쓰고, 가만히(팬 정지) 상태에서 속도를 올리는 쪽으로만 시험해요.
- CPU·GPU 최고 온도가 95 °C 이상이면 바로 멈추고 되돌려요.
- 끝날 때, Control-C나 종료 신호를 받았을 때 진단 도구가 되돌리고, `measure.sh`도 끝날 때 한 번 더 `restore`를 실행해요(수동 모드(1)인 팬만 0으로).
- 다른 팬 제어 앱(Macs Fan Control, TG Pro 등)이 켜져 있으면 시작하지 않아요.
- 그래도 수동 모드로 남으면 Mac을 재시동하면 시스템 제어로 돌아가요.

## 구성

- `fan_probe.swift`: `info`(팬 키 목록) · `unpriv-write`(권한 없는 쓰기 시험) · `control`(관리자 권한, 1초마다 기록) · `restore`(되돌리기). SMC 구조체 배치는 SensorProbe와 같아요
- `measure.sh`: 위 순서로 실행. 제어 단계만 sudo
- `results/`: 결과 원본

| 단계 | 하는 일 | 시간 |
|---|---|---|
| A-기준 | 그대로 기록 | 10초 |
| B-수동 | 모든 팬 `Md = 1` | 6초 |
| C-2500 | 목표 2,500 RPM | 20초 |
| D-3500 | 목표 3,500 RPM | 20초 |
| E-2000 | 목표 2,000 RPM | 15초 |
| F-복원 | 모든 팬 `Md = 0` | 25초 |

## 실행

터미널에서 (앞에 sudo를 붙이지 마세요):

```
bash ~/Desktop/MonitorTool/MonitorTool/Diagnostics/FanProbe/measure.sh
```

## 결과

2026-10-30, macOS 27.2(26B123), 가만히(CPU 45~51 °C). 원본은 `results/`.

**1) 키와 권한**

- 팬 키 25개. `Ftst`·`F0md`·`FS! `는 없어요 → M1 방식(모드 키에 바로 쓰기).
- 속성 바이트: 쓰기 대상 `F{i}Md` 0xd0, `F{i}Tg` 0xd4(그리고 `FBAD` 0xd0, `FOFC` 0xc0)는 0x40 비트가 켜져 있고, 읽기 전용으로 보이는 `Ac`·`Mn`·`FNum` 등은 0x80·0x84로 꺼져 있어요. 0x40이 '쓰기 가능'으로 보이지만 문서로 확인한 것은 아니라 앱에서는 판단에 쓰지 않아요.
- 관리자 권한 없이 쓰면 SMC까지 가지 않고 IOKit 단계에서 `kIOReturnNotPrivileged`(0xe00002c1)로 거절돼요 → 팬 제어는 보조 프로그램(관리자 권한)이 해야 해요.

**2) 관리자 권한으로 제어**

| 단계 | 결과 |
|---|---|
| `Md = 1` | 바로 받아들여짐(SMC 오류 없음). 쓴 직후 다시 읽으면 예전 값, 1초 뒤 읽으면 새 값 |
| 수동인데 `Tg = 0` | 팬 정지 그대로 (6초) |
| `Tg = 2,500` | 1초 뒤 돌기 시작, 약 5초에 도달(한 번 2,659·2,679까지 넘었다 내려옴), 이후 ±1%(2,481~2,516) |
| `Tg = 3,500` | 약 3~4초에 도달, 이후 ±1.5%(3,460~3,525) |
| `Tg = 2,000` | 약 3초에 내려옴, 이후 ±1.5%(1,971~2,027) |
| 유지 | 62초 동안 시스템(thermalmonitord)이 모드를 도로 가져가지 않음 |
| `Md = 0` | 1초 안에 두 팬 모두 정지(가만히라 시스템이 0을 고름), `Tg`도 0. 약 11초 뒤 모드가 0 → 3(시스템)으로 바뀜 |

- 두 팬(최대 4,296·4,744 RPM)에 같은 목표를 줘도 실제 RPM은 거의 같았어요.
- 끝난 뒤 두 팬 모두 `Md = 3`, `measure.sh`의 마지막 `restore`는 쓸 것이 없었어요.

**3) 덤으로 본 것**

- GPU 온도 키(`Tg05`·`Tg0D`)가 가만히일 때 1~2초 간격으로 9.2 °C를 줄 때가 많았어요(두 키 모두 꺼짐에 가까운 값). 앱의 GPU 최고 온도는 0만 '센서 꺼짐'으로 거르고 있어서 9.2 °C가 그대로 보일 수 있어요 → 따로 확인할 일.

**결정에 쓸 것**

- 제어 순서: 보조 프로그램이 `F{i}Md = 1` → `F{i}Tg = 목표`(최소~최대 안). 시스템으로 돌려줄 때 `F{i}Md = 0`(3을 쓰지 않음, 시스템이 스스로 3으로 바꿈).
- 쓴 값은 다음 수집(1초 뒤)에 확인. 실제 RPM은 3~5초에 목표 ±1.5% 안.
- 아직 모르는 것: 잠자기·깨어남 뒤 수동 모드가 남는지, 부하로 뜨거울 때 시스템이 모드를 가져가는지, 보조 프로그램이 끝나거나 앱이 꺼질 때의 복원(앱에 넣을 때 확인).
