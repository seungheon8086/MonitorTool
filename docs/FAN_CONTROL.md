# 팬 제어 설계

작성: 2026-10-30 · 브랜치: `FanController` (`main`의 `9e46d0b`에서 분기)

상태: **동작 설계 확정(2026-10-30).** 사용자와 정한 것(아래 '확정한 범위')과 진단으로 확인한 사실을 바탕으로 한다. 다음은 화면 시안, 그 뒤 보조 프로그램 구현.

설계 문서(`PROJECT_DESIGN.md`) 8장의 선택 단계 '팬 RPM 조절(패널 전용)'에 해당한다. 그 문서는 다른 쪽에서 관리하므로 팬 제어 설계는 이 문서에 따로 적는다.

## 확정한 범위 (2026-10-30 사용자 결정)

- 모드는 **시스템 자동**과 **고정 RPM** 두 가지뿐이다. 온도 곡선 같은 다른 방식은 넣지 않는다.
- 고정 RPM은 **사용자 지정 프리셋**을 여러 개 만들어 고른다. **프리셋 이름은 사용자가 직접 입력**한다.
- **왼쪽·오른쪽 팬을 따로 정한다.** 두 팬이 같은 속도로 돌면 풍절음(맥놀이)이 생기므로 한 값으로 묶지 않는다. 두 값이 가까워도 경고하지 않는다(사용자가 알아서 정함).
- 팬마다 **정지**도 고를 수 있다.
- 고정 RPM은 **정한 시간이 지나면 시스템 제어로 돌아간다.** 시간은 사용자가 정하고, **계속 유지**도 고를 수 있다.
- **잠들 때** 시스템 제어로 돌려놓고, 깨어난 뒤 남은 시간이 있으면 다시 적용한다.
- 복귀 시간 선택지는 **5분 · 15분 · 30분 · 60분 · 직접 입력 · 계속 유지**.
- 프리셋 없이 그 자리에서 좌우 값을 정해 적용하는 **직접 정하기**도 있다.
- 프리셋 이름 **길이 제한은 두지 않는다**(필요하면 사용자가 나중에 정함).
- 고정 RPM 중 **macOS 열 압력이 '보통'을 벗어나거나 CPU·GPU 최고 온도가 95 °C 이상이면** 시스템 제어로 돌아간다.
- **앱이 꺼지면**('계속 유지'라도) 시스템 제어로 돌아간다.

## 팬 이름

| 화면 이름 | SMC | 최소 | 최대 |
|---|---|---|---|
| 왼쪽 | 팬 0 (`F0…`) | 1,499 RPM | 4,296 RPM |
| 오른쪽 | 팬 1 (`F1…`) | 1,499 RPM | 4,744 RPM |

왼쪽·오른쪽 대응은 사용자가 확인했다(2026-10-30). 다른 Mac(팬이 하나이거나 최대값이 같은 경우)은 고려하지 않는 개인용이지만, 코드에서는 `FNum`·`Mn`·`Mx`를 읽어 쓰고 팬이 두 개가 아니면 '팬 1·팬 2'로 표시한다.

**앱 전체를 왼쪽·오른쪽으로 통일**(2026-10-30 사용자 결정). 팬 제어뿐 아니라 지금 '팬 1·팬 2'·'Fan1·Fan2'로 적힌 곳을 모두 바꾸고, 색은 **왼쪽 = 연하게(같은 색의 연한 색, 점선), 오른쪽 = 진하게(항목 색, 실선)**로 지금과 반대로 한다.

| 곳 | 지금 | 바꿀 것 |
|---|---|---|
| 설정 '모양' 온도·팬 설명 (`MonitorItem.swift`) | Fan1 : 진하게, Fan2 : 연하게 | 왼쪽 : 연하게, 오른쪽 : 진하게 |
| 설정 '모양' 미리보기 (`AppearanceSettingsView.swift`) | 두 번째 계열 = 팬 2 | 연한 선 = 왼쪽 |
| 패널 온도·팬 카드 (`SectionCards.swift`) | 팬 1 · 팬 2 | 왼쪽 · 오른쪽 |
| 패널 팬 그래프·팬 칸 (`SystemDetails.swift`) | 팬 1 진한 실선, 팬 2 연한 점선 / '팬 1 · 정지' | 왼쪽 연한 점선, 오른쪽 진한 실선 / '왼쪽 · 정지' |
| 주석 (`ItemColor.swift`, `HistoryChart.swift`, `ChartLegend.swift`) | 팬 2 | 왼쪽 팬 |

이름은 한 곳(`Model/FanName.swift`: 팬이 두 개면 0 → 왼쪽, 1 → 오른쪽, 그 밖은 '팬 n')에서 정하고, 연한·진한 구분도 '왼쪽 팬이면 연하게'를 한 곳에서 정해 모든 화면이 따르게 한다.

## 진단으로 확인한 사실

자세한 표와 원본은 [`Diagnostics/FanProbe/README.md`](../Diagnostics/FanProbe/README.md). macOS 27.2(26B123), MacBookPro18,1.

- 관리자 권한 없이 쓰면 IOKit 단계에서 `kIOReturnNotPrivileged`(0xe00002c1)로 거절된다 → **팬 제어는 보조 프로그램(관리자 권한, LaunchDaemon)이 한다.**
- `Ftst`가 없다(M1 방식). `F{i}Md = 1`(수동)이 바로 받아들여지고, 그 뒤 `F{i}Tg`(목표 RPM, flt)를 쓰면 따라간다.
- 목표에는 3~5초에 도달하고 이후 ±1.5% 안이다. 좌우에 다른 목표(2,000 · 2,300)를 각각 지킨다.
- 돌고 있는 팬에 `Tg = 0`을 쓰면 1초 안에 멈춘다(최소 RPM에 붙잡히지 않음).
- 수동 모드 중 시스템이 제어를 도로 가져가지 않았다(가만히 62초, 30 W 부하 중 25초).
- `Md`: **1 = 수동, 0 = 시스템이 팬을 돌리는 중, 3 = 시스템이 팬을 멈춘 상태.** 시스템 제어로 돌려줄 때는 `Md = 0`을 쓰면 시스템이 알아서 0이나 3으로 정한다. 앱은 0·3을 모두 '시스템 제어'로 표시한다(지금 `ThermalCollector.fanMode`와 같음).
- 쓴 값은 쓴 직후에 읽으면 예전 값이고 1초 뒤에 새 값이다.
- 30 W 안팎(CPU+GPU+ANE)에서 시스템은 CPU 87 · GPU 90 °C에서 팬을 켜고 최소 근처(왼쪽 1,522 · 오른쪽 1,643)로만 돌리며, CPU 83~85 · GPU 86~89 °C를 유지한다. 이때 macOS 열 압력은 줄곧 '보통'이었다. 시스템도 좌우에 다른 속도를 준다.
- 팬이 멈춘 채 뜨거운 칩은 초당 약 0.3 °C 오른다.
- 프로세스가 끝나도 SMC는 수동 모드를 스스로 풀지 않는 것으로 보인다(진단 도구는 끝날 때 직접 되돌렸다). 잠자기·깨어남, 보조 프로그램 강제 종료 때의 동작은 구현 뒤 점검한다.

## 데이터 모델

```
FanTarget      = 정지 | RPM(정수)          // RPM은 그 팬의 최소~최대 안
FanPreset      = id, 이름(사용자 입력), 왼쪽: FanTarget, 오른쪽: FanTarget
FanHold        = 분(정수) | 계속 유지      // 복귀 시간
FanControlRequest (앱 → 보조 프로그램)
               = 시스템 자동
               | 고정(팬별 FanTarget, 끝나는 시각 또는 계속 유지, 프리셋 이름 또는 '직접 정하기')
FanControlState (보조 프로그램 → 앱)
               = 지금 요청, 끝나는 시각, 마지막으로 시스템 제어로 돌아간 이유·시각
```

- 프리셋과 기본 복귀 시간은 **앱**이 UserDefaults에 JSON으로 저장한다(보조 프로그램은 프리셋을 모른다).
- 보조 프로그램은 요청 하나만 기억한다(메모리). 디스크에 남기지 않으므로 보조 프로그램이 다시 뜨면 항상 시스템 제어에서 시작한다.
- 이름: 비어 있으면 저장하지 않는다. 같은 이름도 허용한다(id로 구분). 길이 제한은 두지 않는다(화면에서 넘치면 말줄임).
- 직접 정하기로 정한 값은 프리셋으로 저장하지 않는다. 마지막에 쓴 값만 앱이 기억해 다음 직접 정하기의 처음 값으로 쓴다.
- RPM 입력은 정수, 100 단위로 올리고 내리는 단추 + 직접 입력. 범위 밖은 저장하지 않고 범위를 보여준다.

## 복귀 시간

- 프리셋이나 직접 정하기를 적용할 때마다 고른다. 선택지: **5분 · 15분 · 30분 · 60분 · 직접 입력(분) · 계속 유지**. 미리 골라져 있는 값은 설정 창에서 정한 기본값.
- 끝나는 시각은 벽시계 기준으로 보조 프로그램이 기억한다. 잠든 시간도 흐른 것으로 센다(깨어났을 때 이미 지났으면 시스템 제어 그대로).
- 남은 시간은 패널에 보여준다. 계속 유지면 '계속 유지'.

## 안전장치

모두 **보조 프로그램 안**에서 동작한다. 앱이 멈추거나 강제로 꺼져도 지켜지게 하려는 것이다. 보조 프로그램은 고정 RPM을 맡은 동안 **1초마다** SMC를 직접 읽어 확인한다(앱의 수집 주기와 무관).

시스템 제어로 돌아가는 경우:

| 경우 | 동작 | 패널에 보일 이유 |
|---|---|---|
| 복귀 시간이 지남 | 시스템 제어로 | '시간 종료' |
| macOS 열 압력이 '보통'(0)을 벗어남 | 시스템 제어로 | '열 압력 상승' |
| CPU·GPU 최고 온도 ≥ 95 °C | 시스템 제어로 | 'CPU 온도 95 °C 이상' 또는 'GPU 온도 95 °C 이상' |
| 앱과의 연결이 모두 끊김(앱 종료·강제 종료 포함) | 바로 시스템 제어로 | (다음 연결 때) '앱 종료' |
| 보조 프로그램이 끝남(SIGTERM, 새 실행 파일로 교체) | 끝나기 전에 시스템 제어로 | — |
| 잠들기 직전 | 시스템 제어로, 요청은 기억 | — |
| 깨어남 | 끝나는 시각이 남았으면 다시 적용, 지났으면 그대로 | 지났으면 '시간 종료' |
| 우리가 `Md = 1`로 둔 팬이 1이 아니게 됨 | 다시 쓰지 않고 요청을 버림(다른 프로그램과 다투지 않음) | '다른 프로그램의 제어' |
| 보조 프로그램이 시작할 때 `Md = 1`인 팬이 있음 | 맡은 요청이 없으므로 시스템 제어로 정리 | — |

- **온도 기준의 근거**: 시스템은 30 W 부하에서 최소 팬으로 85~90 °C에 머무르고 이를 '보통'으로 본다. 95 °C는 그보다 5 °C 이상 높아 평범한 무거운 작업에서는 걸리지 않고, 열 압력 알림이 늦거나 오지 않을 때의 숫자 기준이 된다. 열 압력은 macOS 자신의 판단이라 우리가 추측한 숫자에 기대지 않아도 된다. 1초마다 확인하므로 정지 중이라도 기준을 넘는 양은 1 °C 안쪽이다. 정지용 기준은 따로 두지 않는다. (2026-10-30 사용자 확정)
- 온도는 앱과 같은 대표 센서(CPU `Tp…` 10개, GPU `Tg05`·`Tg0D`)의 최고값. 가만히일 때 GPU 키가 9.2 °C를 주는 일이 있어(진단 중 발견) 낮은 값은 무시하므로 판단에는 영향이 없다.
- 안전장치로 돌아간 뒤에는 자동으로 다시 적용하지 않는다. 사용자가 다시 골라야 한다.
- **'계속 유지'도 앱이 꺼지면 시스템 제어로 돌아간다**(2026-10-30 사용자 확정). 보조 프로그램은 앱과 연결이 없으면 5초 뒤 끝나도록 되어 있고, 앱 없이 팬을 계속 붙잡아 두면 패널에서 상태를 볼 수 없기 때문이다.
- 목표는 그 팬의 최소~최대 안이거나 정지(0)만 받는다. 보조 프로그램이 다시 확인하고 범위 밖이면 거절한다.

## 보조 프로그램 (XPC 약속 추가)

`HelperProtocol`에 두 함수를 더한다. 지금처럼 정해진 일만 하고 임의의 SMC 키·값은 받지 않는다.

```swift
/// 팬 제어 요청 (FanControlRequest JSON). 답: 적용한 뒤의 FanControlState JSON, 거절 이유
func setFanControl(_ request: Data, reply: @escaping (Data?, String?) -> Void)
/// 지금 상태 (FanControlState JSON)
func fanControlState(reply: @escaping (Data?, String?) -> Void)
```

- 쓰는 키는 `F{i}Md`(0·1)와 `F{i}Tg`뿐이다. 수동으로 바꿀 때 순서: 팬마다 `Md = 1` → `Tg = 목표`. 돌려줄 때: 팬마다 `Md = 0`.
- 쓰기 결과는 1초 뒤 다시 읽어 확인한다. 3초 안에 반영되지 않으면 시스템 제어로 돌리고 실패를 알린다.
- 앱은 지금처럼 수집 때 `fanControlState`를 함께 묻고, 패널을 열 때 한 번 더 묻는다.
- 연결 끊김은 지금 `HelperLifecycle`이 세는 연결 수로 안다. 0이 되면 팬은 바로 돌려주고, 보조 프로그램 종료는 지금처럼 5초 뒤.
- 잠자기·깨어남은 보조 프로그램이 `IORegisterForSystemPower`로 받는다.
- SMC 쓰기 코드는 보조 프로그램 타깃에만 둔다. 앱의 `SMC.swift`는 지금처럼 읽기만 한다.
- 보조 프로그램이 꺼져 있거나 허용이 필요하면 패널 팬 제어부에 '보조 프로그램 허용하기'를 보여준다(지금 전력 표시와 같은 흐름).

**설정 창: 새 '팬' 탭** (일반 · 모양 · 보조 프로그램 · 팬)

- 편집·추가는 그 줄이 펼쳐짐: 이름(제한 없음), 팬마다 정지 + RPM, 취소·저장(이름이 비었거나 범위 밖이면 저장 꺼짐).
- '기본 복귀 시간': 패널과 같은 여섯 가지.

**위젯·메뉴 막대**: 이번 범위 밖. 위젯은 처음부터 다시 설계하므로(첫 구현은 `widget-v1` 브랜치에 보관) 팬 표시는 그때 `FanName`을 따라 정한다.

**문구 규칙** (사용자가 `9e46d0b` 'notation 정상화'에서 앱 전체를 맞춘 방식)
- 설명 문단·출처 안내·하는 일 목록은 넣지 않는다.
- 상태·안내는 개조식 명사형: '허용 필요', '시간 종료', '범위 초과', '데이터 수신 대기'. 해요체 문장으로 쓰지 않는다.
- 정상 상태의 세부 줄은 비워 둔다.
- 경로는 `>`(예: 'MonitorTool 설정 > 팬'), 짝은 '·' 또는 'A : B'.

## 구현 순서 (제안)

1. **보조 프로그램**: SMC 쓰기(`FanWriter`), `FanControlCoordinator`(요청 하나, 1초 감시, 안전장치 표의 모든 경우), 시작 정리, 잠자기 알림, XPC 함수 두 개, Shared 모델(`FanTarget`·`FanControlRequest`·`FanControlState`). 규칙(언제 돌려주는지)은 순수 값 타입으로 떼어 Python으로 경우별 시험.
2. **왼쪽·오른쪽 통일**: 위 표의 이름·색 바꾸기(팬 제어와 독립이라 먼저 빌드 확인).
3. **앱 연결**: `HelperController`에 요청·상태 묻기, 프리셋·기본 복귀 시간 저장(`FanPresetStore`), 스냅샷에 제어 상태와 목표 RPM.
4. **설정 '팬' 탭**: 프리셋 편집.
5. **패널 팬 제어부**.
6. **점검**: 시간 만료, 잠자기·깨어남, 앱 강제 종료, 보조 프로그램 강제 종료(`sudo kill -9`) 뒤 다음 시작 때 정리, 다른 프로그램이 모드를 바꿀 때, 온도 안전장치(DEBUG 빌드에서 기준을 낮춰 시험).

단계마다 빌드 확인 뒤 커밋한다.
