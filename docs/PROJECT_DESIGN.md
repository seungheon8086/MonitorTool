# MacMonitorTool 설계 — 구현 전 최종 검토안

수정일: 2026-10-23 · 상태: 요구사항 반영 완료. **확장형 위젯(구형 Today 확장)은 macOS 27.0.1에서 미지원으로 확인. 대안으로 WidgetKit 위젯 안에서 요약 ↔ 상세 화면을 전환하기로 합의(2026-10-22). 위젯 안 전환, App Group 공유, 앱이 뒤에 있을 때의 갱신(앱의 5초 요청을 그대로 반영)까지 실기 확인. 장시간 유지 여부는 실사용 점검에서 확인.** **전력·사용률 검증(2026-10-23): CPU·ANE 전력은 관리자 권한으로만 실시간 측정 가능해 관리자 권한 보조 프로그램으로 수집하기로 합의. E/P·GPU 사용률 정의 합의. ANE 사용률은 이 Mac에서 직접 재는 값이 없어 '측정 불가'로 표시하고, 사용 중 여부와 전력 W를 보여주기로 합의.** 온도·팬 센서 수집은 실기 검증 전. 팬 제어는 마지막 선택 단계.

## 1. 사용자와 확정한 범위

- 개인용 macOS 모니터링 프로그램. 외부 배포는 현재 범위에 포함하지 않는다.
- CPU, RAM, GPU, ANE, 배터리, 네트워크, 온도 센서, 팬별 회전수(RPM)를 표시한다.
- **실시간 별도 패널과 macOS 알림 센터 위젯을 모두 제공한다.**
- **알림 센터 위젯에서 항목을 누르면 알림 센터 안에서 위젯 높이가 늘어나며 그래프와 상세 정보가 표시되어야 한다.** 별도 패널로 이동하거나 같은 크기 안에서 화면만 바꾸는 방식은 이 요구사항의 대체안이 아니다.
- 구형 Today 확장도 사용 가능하다. 최신 WidgetKit 사용 자체는 목표가 아니며, 실제 OS가 요구 동작을 지원하는지가 기술 선택의 기준이다.
- CPU 사용률은 **E-core / P-core를 분리**한다. M1 Pro의 구성 요소별 전력은 **CPU / GPU / ANE 세 항목만** 표시하고, **ANE(Neural Engine)의 사용률 %와 전력 W를 CPU 옆에 배치**한다.
- ANE 사용률은 필수 표시 목표다. 실제 활성 비율을 얻을 수 있는지 먼저 검증하며, 전력을 임의의 최대 전력으로 나눈 값을 사용률로 대신하지 않는다.
- CPU 전력은 CPU 전체 도메인 한 값으로 표시한다. E/P별 전력 분리와 기타 SoC/uncore/DRAM 전력은 현재 범위에서 제외한다.
- 배터리 충전·방전 W는 별도의 배터리 상태 정보로 유지한다.
- 네트워크 업로드·다운로드 각각에 대해 **오늘 누적과 앱 실행 이후 누적**을 제공한다.
- 기본 화면은 핵심 수치 중심이다. **수치를 누르면 그래프와 상세 정보가 펼쳐진다.**
- 온도와 팬 RPM은 두 화면의 기본 모니터링 범위다. **팬 RPM 조절은 기본 앱 완성 후 검토하는 선택 기능이며, 실시간 패널에서만 제공**한다.
- Monit의 빠르게 확인하는 사용 경험을 참고한다.
- (2026-10-22 합의) 메뉴 막대 수치 표시는 팬 제어처럼 기본 앱 완성 후 검토하는 선택 기능이다. 상위 프로세스 목록은 범위에 넣지 않는다. 앱 이름은 MonitorTool로 한다.
- (2026-10-23 합의) CPU·ANE 전력은 관리자 권한으로 도는 작은 보조 프로그램이 `powermetrics`로 읽어 앱에 전달한다. 보조 프로그램이 없거나 허용 전이면 CPU·ANE 전력은 `권한 필요` 상태로 표시한다. 개인 팀 서명으로 등록되는지는 진단 앱으로 먼저 확인한다. 선택 단계의 팬 제어도 같은 구조를 재사용한다.
- (2026-10-23 합의) E/P 사용률은 OS가 집계한 코어별 CPU 시간 비율(`host_processor_info`)을 E·P 묶음마다 평균한 값으로 한다. GPU 사용률은 IORegistry의 `Device Utilization %`로 한다.
- (2026-10-23 합의) ANE 사용률(%)은 측정 불가로 확인됐다(7장). ANE 칸의 기본 화면은 '사용 중/쉬는 중'(IOReport ANE0 전원 상태)과 전력 W를 보여주고, % 자리는 `— · 측정 불가`와 이유를 표시한다. 펼친 상세에는 ANE 메모리 트래픽(GB/s) 그래프를 둔다. 전력을 최대 전력으로 나눈 값 같은 추정치는 쓰지 않는다.
- 현재 확인한 개발 기기: MacBookPro18,1, Apple M1 Pro, RAM 16GiB, macOS 27.0.1. Xcode 27.1, macOS 27.0 SDK.

이 문서는 구현 전 검토안이다. 아래의 주기·보관 기간·세부 동작은 설계 제안이며, 실제 앱을 구현하거나 성능을 검증한 결과가 아니다. 기존 화면 시안은 CPU/GPU/ANE 전력, E/P 사용률 분리, 알림 센터 안에서 높이가 늘어나는 동작까지의 개념 시안으로, 이번에 추가한 ANE %, 온도·팬은 아직 반영되지 않았다. 시안의 동작은 macOS 27에서 해당 확장이 실행된다는 증거가 아니며, 실제 호스팅·높이 변경 지원 여부를 먼저 검증한다.

## 2. 화면과 상호작용 제안

### 실시간 패널

- 메뉴 막대 아이콘 또는 설정 가능한 단축키로 오른쪽 패널을 연다.
- 기본 폭 약 380pt. CPU/ANE → GPU → RAM → 온도·팬 → 배터리 → 네트워크 순서를 제안한다. CPU 옆 ANE에는 GPU처럼 사용률 %와 전력 W를 함께 표시한다.
- `온도·팬` 요약에는 CPU/GPU 영역의 대표 온도와 팬별 실제 RPM을 표시한다. 상세에서는 온도 센서 목록과 팬별 그래프를 나누어 펼친다. 팬 제어가 검증되면 이 상세 영역에만 제어부를 추가한다.
- 행 전체와 수치를 클릭할 수 있도록 한다. 선택한 행 바로 아래에 그래프와 상세 정보가 펼쳐진다.
- 여러 항목을 함께 펼칠 수 있다. 화면 높이를 넘으면 상세 내용이 스크롤된다.
- 닫았다 열면 펼친 항목을 같은 앱 실행 내에서 유지한다.
- 기본 닫기 동작은 바깥 클릭 또는 Escape. Dock에는 상시 아이콘을 두지 않는 메뉴 막대 앱을 제안한다.
- 키보드 조작, VoiceOver 레이블, 시스템 라이트·다크 모드를 지원한다.
- 전체 화면 앱·여러 모니터에서의 표시 위치는 패널 구현 단계에서 실제 동작을 검증한다.

### 알림 센터 확장형 위젯 — 필수 UX, 현재 OS 지원 미검증

> **2026-10-22 변경:** 구형 Today 확장이 macOS 27.0.1에서 등록되지 않아(7장 검증 결과) 아래의 높이 확장은 구현할 수 없다. 사용자와 합의해 **WidgetKit 위젯의 같은 크기 안에서 버튼으로 요약 ↔ 상세(그래프) 화면을 전환**하는 방식으로 대체한다. 수치에 측정 시각을 함께 표시하는 원칙은 그대로 유지한다. 아래 원래 요구는 결정 과정의 기록으로 남긴다.

- 접힌 상태에서는 핵심 수치를 표시한다. 수치를 누르면 **위젯 외곽 높이가 늘어나고 해당 행 아래에 그래프·상세 정보가 생긴다.** 다시 누르면 해당 상세 영역이 접힌다.
- 이 과정에서 알림 센터를 벗어나거나 별도 앱 창으로 이동하지 않는다.
- 고정 크기 위젯의 내용 전환은 사용자가 대체안으로 선택하지 않았다. 별도 패널은 독립적인 보기 수단이며 위젯의 펼침 기능을 대신하지 않는다.
- 구형 Today 확장의 `preferredContentSize.height`가 우선 검증 대상이다. 현재 SDK의 `NCWidgetProviding.h`에는 높이 변경 설명이 남아 있고, macOS 11부터 deprecated로 표기되어 있다.
- API·프레임워크가 남아 있다는 사실과 현재 알림 센터가 확장을 실제로 호스팅한다는 사실은 구분한다. 현재 Mac에서 구형 확장의 등록·표시·높이 변경은 아직 검증하지 않았다.
- WidgetKit의 정해진 크기 종류를 선택하는 기능은 클릭에 따라 위젯 외곽 높이를 자유롭게 변경하는 기능과 다르다. 현시점에서 요구사항을 충족하는 WidgetKit의 공식 동적 높이 API를 확인하지 못했다.
- 구형 확장 검증이 실패하면 요구사항이 충족되지 않았다고 보고한다. 사용자 합의 없이 고정 크기 위젯이나 별도 패널로 바꿔 완성 처리하지 않는다.
- 수치에는 **실제 측정 시각**을 포함한다. 갱신이 정지한 값은 현재 실시간 값처럼 표현하지 않는다.
- ANE %, 온도·팬도 같은 위젯 안에서 펼친다. 팬 모드와 RPM은 조회만 가능하며, 위젯에는 제어 명령을 넣지 않는다.
- 네트워크 누적에는 기준 날짜를 포함한다. 자정 이후 전날 스냅샷을 읽으면 전날 값을 ‘오늘 누적’이라고 표시하지 않는다.
- 아직 데이터가 없으면 측정 준비 상태를 표시한다. 오래된 값·수집 실패·미지원 전력을 0으로 바꾸지 않는다.
- 구형 위젯이 동작하더라도 표시 중 타이머·수집기 연결·숨김 시 중단 정책을 별도로 검증한다. 초 단위 실시간 갱신도 현재 미확정이다.

## 3. 표시할 수치

| 항목 | 접힌 상태 | 펼친 상태의 초기 제안 |
|---|---|---|
| CPU | E-core 사용률, P-core 사용률, CPU 전력 W | E/P 각각의 사용률 그래프, CPU 전력 그래프, 코어별 정보 |
| CPU 옆: ANE | ANE 사용률 %, 전력 W → (2026-10-23) 사용 중 여부, 전력 W, %는 측정 불가 표시 | 사용률·전력 그래프, 사용률의 정의와 측정 범위 → (2026-10-23) 전력·메모리 트래픽 그래프, 측정 범위 설명 |
| RAM | 사용량/전체 용량, 사용률 | 사용량 그래프, 메모리 압력, 압축 메모리, 스왑 |
| GPU | 전체 사용률, GPU 전력 W | 사용률·전력 그래프, 측정 가능한 GPU 정보 |
| 온도·팬 | CPU/GPU 영역 대표 온도 °C, 팬별 실제 RPM | 센서별 온도·그래프, 팬별 RPM 그래프·모드·지원 범위; 선택 단계 완료 후 패널에만 제어부 |
| 배터리 | 잔량, 충전/방전/보류 상태, W, 예상 시간 | 순전력 그래프, 성능 상태, 사이클 수 |
| 네트워크 | 업로드·다운로드 속도, 오늘 누적 | 업/다운 그래프, 오늘·이번 실행 누적, 인터페이스별 수치 |

- 배터리 W는 배터리에 유입·유출되는 **순전력**이다. 충전기 정격 출력이나 콘센트에서 측정한 Mac 전체 소비전력과 구분한다.
- 배터리 시간은 OS가 제공하는 추정치를 우선한다. 계산 중, 알 수 없음, 완충, 충전 보류, AC 연결 상태를 구분한다.
- 메모리 압력은 시스템에서 얻는 상태를 우선한다. RAM 사용률만으로 녹색/노란색/빨간색을 결정하지 않는다.
- Apple Silicon의 통합 메모리 특성을 고려해 GPU 메모리와 시스템 RAM을 별개 용량처럼 더하지 않는다.
- E/P 사용률은 각 그룹 안에서 0–100%로 정규화한다. 코어 수와 그룹 배치는 실제 기기에서 확인하며 고정된 코어 순서를 가정하지 않는다. 전체 사용률을 추가한다면 코어 수로 가중한다. 코어와 묶음의 대응은 IODeviceTree의 `cluster-type`으로 읽는 방안을 진단에서 확인한다. → (2026-10-23) 확인: CPU 0·1은 E, 2~5는 P(묶음 1), 6~9는 P(묶음 2).
- CPU의 동작 시간 비율, OS CPU 시간 비율, 주파수를 반영한 성능 비율은 서로 다른 지표다. 수집 경로를 검증한 후 E/P 사용률의 정의를 하나로 정하고 그래프에 일관되게 사용한다. → (2026-10-23) OS CPU 시간 비율의 묶음별 평균으로 정했다. 같은 구간에서 코어별 HW 활성 비율보다 0~4%p 낮았고, 묶음(클러스터) 활성 비율은 '코어가 하나라도 일한 시간'이라 뜻이 다르다(`Diagnostics/PowerProbe` 2차).
- CPU 전력은 전체 CPU 도메인 한 값으로 표시한다. E/P 사용률은 분리하되, 이를 기준으로 CPU 전력을 임의 배분하지 않는다.
- (2026-10-23) GPU 사용률은 IORegistry의 `Device Utilization %`로 표시한다. GPU 활성 시간 비율(IOReport `GPUPH`, powermetrics와 같은 값)은 GPU가 잠깐씩만 일해도 높게 나와서(ANE 작업 중 40%, 같은 때 Device Utilization 4.5%) 기본 지표로 쓰지 않는다.
- CPU 옆 영역의 표시명은 `ANE`이며, 상세 정보에서 `Neural Engine`으로 풀어 쓴다. 사용률과 전력은 독립 지표로 수집하고 상태도 따로 관리한다.
- ANE %의 우선 검증 대상은 샘플 구간의 활성 시간 비율이다. 설치된 `powermetrics` 바이너리에 `ANE … SW active residency` 및 `idle residency` 출력 문자열이 존재하지만, 이것만으로 M1 Pro에서 출력되거나 실제 연산 점유율을 뜻한다고 단정하지 않는다. 실제 출력·갱신·정의·유휴/부하 반응을 확인한 뒤 UI 설명을 확정한다. → (2026-10-23) M1 Pro·macOS 27.0.1의 `powermetrics` 출력(기본, `--show-all`)에는 ANE 활성 비율이 없었다. 대신 관리자 권한 없이 읽히는 IOReport `SoC Stats / Cluster Power States / ANE0`의 ACT 시간 비율이 ANE 작업에서만 100%, 가만히·CPU·GPU 작업에서 0%로 반응했다. 이 값은 ANE 전원 상태의 비율이라 실제 연산 점유율과 같다고 단정하지 않는다. 부분 부하에서 일한 양에 비례하는지 3차 진단에서 확인한다. → (2026-10-23) 비례하지 않았다. 초당 4회만 요청해도 ACT 비율이 100%에 머물러, 이 값은 일한 시간이 아니라 전원이 켜져 있던 시간이다. ANE 메모리 트래픽(IOReport `AMC Stats / Perf Counters / ANE0 RD·WR`)은 요청 1회당 약 57~61 MB로 일한 양에 비례했다. 그래서 ANE %는 측정 불가로 표시하고, ACT 비율은 '사용 중' 여부에만 쓴다.
- ANE 전력만 읽히면 W는 표시하고 %는 `— · 측정 불가`로 남긴다. 이는 ANE % 요구사항을 충족한 상태가 아니며, 확보 실패 시 그 결과를 사용자와 검토한다. 최대 W 대비 비율이나 이론 TOPS 비율로 대체하지 않는다.
- CPU/GPU/ANE 전력은 샘플 구간의 추정 평균 W로 다룬다. 충전기·배터리·시스템 전체 전력과 범위를 구분한다.
- CPU+GPU+ANE 합계를 칩 전체 또는 Mac 전체 전력으로 표시하지 않는다. 배터리 충·방전 W는 세 구성 요소 전력의 합계와 별개다.
- 대표 온도는 **검증된 CPU 영역 센서 중 최고값 / GPU 영역 센서 중 최고값**을 초기 제안으로 한다. UI에는 `CPU 최고`, `GPU 최고`처럼 집계 의미를 표시한다. 이는 칩 전체의 절대 최고 온도를 보장하는 값이 아니다.
- 상세에는 실제 확인한 센서 이름·출처·°C를 제공한다. 배터리·SSD 등은 검증된 센서가 있을 때 추가하며, 위치를 모르는 센서를 임의로 CPU 코어 또는 ANE 온도라고 부르지 않는다. 같은 센서의 중복 노출도 제거한다.
- 팬은 탐지한 개수와 ID를 기준으로 각각 표시한다. 위치가 확인되기 전에는 `팬 1`, `팬 2`로 표기하며 좌/우·개수·RPM 범위를 고정하지 않는다. 정상적인 0 RPM과 읽기 실패를 구분한다.
- 온도는 0°C로, 읽지 못한 RPM은 0 RPM으로 대체하지 않는다. 팬의 요청 목표 RPM, 읽어 확인한 목표 RPM, 실제 회전수는 서로 다른 값이다.
- 네트워크 속도는 기본 B/s, KB/s, MB/s 자동 단위로 표시한다. 누적량은 MB/GB로 표시하며 내부에는 원본 바이트를 저장한다.
- 값마다 출처, 단위, 측정 구간, 측정 시각과 정상/준비 중/미지원/권한 필요/오류/오래됨 상태를 함께 가진다. 지원 여부는 지표별로 관리하며, 한 센서의 실패가 전체 화면을 막지 않는다.

## 4. 수집과 그래프의 기본값 제안

| 상태 | CPU/RAM/GPU | 온도·팬 RPM | 네트워크 | 배터리 |
|---|---|---|---|---|
| 패널이 열려 있음 | 약 1초 | 약 1–2초 | 약 1초 | 약 5초 |
| 두 화면 모두 숨김 | 약 10초 | 약 10초 | 약 5초 | 약 30초 |
| 시스템 절전 | 수집 중단 | 수집 중단 | 수집 중단 | 수집 중단 |

- 센서 자체의 갱신 빈도는 별개다. 읽기 주기가 실제 새 측정값 발생 주기를 뜻하지 않는다.
- 최근 **30분**을 메모리의 제한된 버퍼에 보관하고, 상세 화면에서 1분/5분/30분을 선택하는 구성을 제안한다.
- 기본 그래프는 최근 1분이다. 숨긴 동안에는 낮은 빈도로 수집된 실제 시각을 그대로 사용한다.
- 앱을 시작하기 전 기록은 만들지 않는다. 절전·수집 실패 구간에는 선을 끊고 가짜 0이나 보간된 정밀한 기록을 표시하지 않는다.
- 앱을 종료하면 그래프 기록은 사라진다. 오늘 네트워크 누적과 설정은 유지한다.
- 매초 디스크에 기록하지 않는다. 누적량 및 마지막 위젯용 스냅샷은 묶어서 저장하며, 초기 저장 간격은 약 30초를 제안한다. 이는 UI 갱신 주기가 아니다.
- 위젯 상세 그래프에는 현재값뿐 아니라 제한된 최근 이력이 필요하다. 위젯이 표시되는 동안 검증된 IPC 또는 공유 이력 전달 경로로 메인 앱의 기록을 제공한다. 시간 구간 요청·응답 크기를 제한하며, 영속 저장 주기와 분리한다.
- 위젯만 표시된 경우도 활성 소비자로 처리할 수 있는지 검증한다. 가능하면 필요한 지표의 수집 주기를 높이고, 불가능하면 실제 측정 시각과 공백을 그대로 보여준다. 앱 종료·통신 실패 시 마지막 스냅샷을 실시간으로 표시하지 않는다.
- 패널이 닫히면 렌더링을 중단한다. 수집 주기는 실제 CPU 사용·에너지 영향을 측정한 뒤 조정한다.
- CPU/GPU/ANE 전력 및 ANE % 수집 주기는 별도로 측정한다. 초기 목표는 표시 중 1초 구간이지만, 권한·센서 갱신·추가 전력 소모를 확인하기 전에는 확정하지 않는다.
- 센서 목록은 초기화 및 필요할 때 다시 탐색하고, 매 표본마다 전체 SMC 키를 재탐색하지 않는다.
- 팬 수동 제어가 활성화된 경우에는 패널 표시 여부와 무관하게 제어 감시 주기를 유지한다. 숨김 시의 일반 모니터링 절전 정책과 분리한다.
- 위 표의 주기는 별도 실시간 패널 기준이다. 알림 센터 위젯의 표시 여부와 갱신 제어는 선택한 확장 기술에서 따로 검증한다.

## 5. 네트워크 누적의 의미

### 오늘 누적

- **오늘 앱이 관측하고 기록한 트래픽의 합계**다. 통신사 과금량이나 앱 설치 전·종료 중 사용량을 의미하지 않는다.
- 로컬 달력의 날짜별로 업/다운 값을 저장하고, 같은 날짜에 앱을 재실행하면 복구한다.
- 앱 미실행 구간은 수집 공백으로 다루며, 이미 저장된 오늘 값은 유지한다.
- 갑작스러운 앱 종료에는 마지막 저장 이후 일부 관측값을 잃을 수 있다. 정상 종료 때는 추가 저장한다.
- 자정 전후에는 가능한 한 경계 샘플을 수집한다. 자정을 걸친 샘플이나 절전 구간의 날짜별 배분이 불명확하면 추정/공백임을 기록한다.
- 시간대·시각 변경을 처리하며, 날짜 분류와 속도 계산용 시계는 분리한다.

### 앱 실행 이후 누적

- 프로세스가 새로 시작될 때 0부터 시작한다. 앱 재실행은 새 세션이다.
- 패널을 닫거나 Mac이 잠들었다 깨어나는 것은 새 세션이 아니다.
- 절전 중 수집하지 못한 트래픽은 관측 범위를 넘어 보장하지 않는다. 복귀 시 새 속도 기준점을 잡아 비정상적인 급등을 방지한다.

### 집계 범위

- 기본 총량은 Wi-Fi/Ethernet 등 실제 전송 인터페이스 기준으로 집계한다. LAN 전송도 포함한다.
- VPN 가상 인터페이스, loopback 등을 물리 인터페이스와 중복 합산하지 않는다.
- 인터페이스마다 누적 바이트 카운터와 기준점을 관리한다. 감소·재생성·재부팅을 새 기준점으로 처리한다.
- 속도는 실제 경과 시간으로 계산한다. 인터페이스 전환·연결 해제·첫 표본에는 유효한 두 표본이 생길 때까지 속도를 미확정으로 표시한다.
- 여러 어댑터·브리지·VPN 사용 상황에서의 집계는 검증 항목이다.

## 6. 기술 구조

Swift를 중심으로 공통 수집·저장 계층을 구성한다. 별도 패널에는 SwiftUI/AppKit을 사용하며, 알림 센터 UI는 요구하는 높이 확장이 실제 동작하는 확장 기술을 검증한 뒤 선택한다. 구형 Today가 가능하다면 AppKit 기반 확장도 수용한다.

```text
macOS 측정 API
       ↓
메인 앱: 수집기 → 공통 데이터 모델
                     ├─ 메모리 상태·최근 그래프 → 실시간 패널
                     ├─ 날짜별 네트워크 누적·설정 → 로컬 저장
                     └─ 공유 데이터 → 알림 센터 확장형 위젯
                                          ↓ 항목 클릭
                                 같은 위젯의 높이 증가·상세 표시

전력·ANE 활성 비율·온도·팬 수집: OS 측정 도구 / 검증된 센서 → 공통 데이터 모델
              (필요 권한과 보조 프로세스 구성은 실측 후 결정)

선택 단계: 실시간 패널 → 제한된 팬 제어 서비스 → 팬 모드/목표 변경
                                      └─ 읽기 확인·연결 감시·자동 복귀
```

- 수집 주체는 메인 앱의 공통 수집 계층 한 곳으로 통일한다. 권한이 필요한 읽기만 제한된 보조 프로세스에 위임할 수 있으며, 위젯은 센서를 별도로 폴링하지 않는다.
- CPU/RAM은 Mach/sysctl, 배터리 상태·ETA는 IOPowerSources, 네트워크는 인터페이스 바이트 카운터를 우선한다.
- GPU 이용률, 배터리 W, E/P 분류, CPU/GPU/ANE 전력, ANE %, 온도 및 팬 수치는 기기와 OS에 의존할 수 있다. 작은 수집 모듈로 격리하고 실제 M1 Pro에서 검증한다.
- 온도·팬 읽기는 SMC와 Apple Silicon 센서 접근 구현을 참고하되, 키 매핑·데이터 타입·읽기 권한을 현재 기기에서 확인한다. 비공개 경로는 OS 업데이트 후 재검증한다. 센서 수집과 팬 제어 명령 계층은 분리한다.
- 측정·집계는 UI 실행 흐름을 막지 않도록 분리한다. 네트워크 누적 갱신은 단일 소유자가 처리한다.
- 위젯과 앱은 공통 Codable 모델을 공유한다. 버전, 실행 세션, 측정 시각·구간, 출처, 단위, 값 상태, 센서/팬 ID 및 제한된 최근 이력을 포함한다. 새 실행의 기록에 이전 실행 스냅샷을 섞지 않는다.
- 공유 데이터는 메인 앱 단독 쓰기, 확장 읽기 원칙을 적용한다. App Group/통신 경로는 실제로 호스팅되는 확장 기술과 로컬 서명 조건을 확인한 뒤 결정한다.
- WidgetKit을 검토할 경우 기존 갱신 예산 제한은 유지된다. 상주 앱이 있다고 해서 초 단위 reload가 보장되는 것으로 설계하지 않는다.
- CPU/GPU/ANE 전력의 1차 기준 측정은 macOS 기본 `powermetrics`를 검토한다. 현재 설치된 도구의 도움말에서 세 샘플러를 확인했으며, 실제 값은 아직 읽지 않았다. → (2026-10-22) 세 값 모두 mW 단위로 읽었고, ANE 전력은 ANE 작업에서만 반응했다(`Diagnostics/PowerProbe` 1차).
- macmon 개발자는 macOS 27에서 기존 IOReport Energy Model CPU/ANE 카운터 갱신에 제약이 생겼다고 보고한다. 새 비공개 카운터 우회 방식이 있더라도 모든 기기에서 안정적으로 된다고 가정하지 않는다. → (2026-10-22) 이 Mac에서도 관리자 권한 없이 읽은 CPU·ANE·DRAM 에너지 카운터는 `powermetrics`가 도는 동안에만 갱신됐다. GPU 에너지(`GPU Energy`, nJ)만 권한 없이 계속 갱신됐다.
- 전력 수집에 관리자 권한이 필요할 수 있다. 앱 전체를 root로 실행하는 설계는 피하고, 실제 검증 후 필요한 최소 수집 기능을 분리하는 방안을 검토한다. 현재 보조 도구 설치나 권한 변경은 수행하지 않았다. → (2026-10-23 합의) 관리자 권한 보조 프로그램(`SMAppService`로 등록하는 LaunchDaemon)이 `powermetrics`를 정해진 인자로만 실행해 CPU·ANE 전력을 앱에 전달한다. 앱과는 XPC로 통신하고, 같은 팀 서명의 앱 요청만 받는다. GPU 전력, E/P·GPU 사용률, ANE 전원 상태 비율은 보조 프로그램 없이 메인 앱이 읽는다.
- 로그인 시 실행 옵션을 제공한다. 실제 자동 실행 활성화는 사용자의 설정 선택에 따른다.

## 7. 구현 전에 검증할 기술 사항

1. **최우선: 구형 Today 확장의 실제 동작 확인.** 더미 수치와 펼침 버튼만 있는 작은 진단용 확장을 준비하고, 알림 센터 등록·표시·높이 증가/복원·주변 위젯 재배치를 확인한다.
2. 클릭 후 알림 센터가 유지되는지, 현재 macOS의 표시 중 갱신과 숨김 상태 처리가 가능한지 확인한다.
3. **병행 검증: CPU/GPU/ANE 전력 및 ANE %.** `powermetrics`의 제한된 샘플을 기준으로 세 도메인의 실제 출력·단위·갱신 여부와 필요한 권한을 확인한다. ANE 활성 비율 필드가 M1 Pro에서 나오는지, 유휴 상태와 ANE 실행이 확인된 작업에서 반응하는지, 활성 상태와 실제 연산의 의미가 어떻게 다른지 확인한다. CPU/GPU로 대체 실행된 작업을 ANE 검증으로 간주하지 않는다.
4. E/P 지표의 실제 출력과 그룹별 사용률 정의를 검증한다. CPU 전력은 하나의 CPU 도메인 값으로 유지한다. ANE % 확보 실패는 별도 미해결 요구로 기록한다.
5. 온도·팬을 **읽기만 하는** 진단으로 센서 목록·매핑·단위, 팬 개수·실제 RPM·가능한 모드 조회, 유효 0과 실패 구분을 확인한다. 이 단계에서는 제어 설정을 변경하지 않는다.
6. 지원되는 확장 기술이 확인된 뒤 공통 수집기·공유 데이터·최근 그래프 이력·로컬 서명을 연결한다. 앱 종료 또는 공유 경로 중단 시의 위젯 표시도 검증한다.
7. CPU/RAM/GPU/배터리/네트워크의 나머지 수집을 구현하고 경계 상황을 검증한다. 팬 제어는 아래 선택 단계에서 따로 검증한다.

현재 완료한 조회: Xcode 27.1/macOS 27.0 SDK 확인, NCWidgetProviding의 높이 조절 설명 및 macOS 11 deprecation 확인, `powermetrics --help`의 CPU/GPU/ANE 샘플러 확인. 구형 확장 등록 목록 조회는 빈 결과였다. 이는 설치된 일치 확장이 없다는 의미이며 OS의 호스팅 지원 종료를 증명하지 않는다.

**검증 결과 (2026-10-22): 구형 Today 확장 미지원.** 진단 앱(`Diagnostics/TodayWidgetProbe`)의 확장은 선언(`com.apple.widget-extension`, `XPC!`)·서명(개인 팀 Apple Development)·샌드박스가 모두 정상이었다. 그러나 macOS 27.0.1의 pluginkit은 확장 경로와 앱 경로로 직접 등록을 시도해도 받아들이지 않았고, 알림 센터 위젯 목록에 나타나지 않았으며, 확장이 실행된 로그도 없었다. 같은 Mac에서 WidgetKit 위젯(`com.apple.widgetkit-extension`)은 정상 등록돼 있다. 따라서 2장의 '알림 센터 안에서 높이가 늘어나는 위젯'은 현재 OS에서 충족할 수 없다. 대안은 사용자와 합의해 WidgetKit 위젯 안에서 요약 ↔ 상세 화면을 전환하는 방식으로 정했다(2026-10-22). 확인 항목별 기록은 진단 앱 README에 있다.

**WidgetKit 대안 검증 (2026-10-22): 동작.** `Diagnostics/WidgetKitProbe`에서 위젯 안 버튼(App Intent)으로 같은 크기 안 요약 ↔ 상세 전환, 알림 센터 유지, 개인 팀 서명의 App Group 공유를 확인했다. 앱이 뒤에 있을 때도 위젯이 앱의 갱신 요청(5초 간격)을 그대로 반영했다. 관찰 시간이 짧아 장시간 유지 여부는 실사용 점검에서 다시 확인한다.

**전력·사용률 검증 (2026-10-22~23, `Diagnostics/PowerProbe`).** 1차에서 `powermetrics`(관리자 권한)로 CPU·GPU·ANE 전력과 E/P·GPU 활성 비율을 읽었다. ANE 전력은 ANE 작업에서만 반응했고 나머지 상태에서는 0 mW였다. 기본 출력과 `--show-all`에는 ANE 활성 비율이 없었다. 2차에서 관리자 권한 없이 IOReport를 읽어 보니 CPU·ANE 에너지 카운터는 `powermetrics`가 도는 동안에만 갱신됐다. 그래서 실시간 CPU·ANE 전력에는 관리자 권한이 필요하다. E/P·GPU 활성 비율, GPU 전력, ANE 전원 상태(ACT) 비율, ANE 메모리 트래픽은 권한 없이 읽혔다. 이 결과로 관리자 권한 보조 프로그램과 E/P·GPU 사용률 정의를 합의했다(2026-10-23, 1장). ANE 사용률은 ACT 비율이 부분 부하에서 일한 양에 비례하는지 3차에서 확인한다.

**ANE 사용률 검증 (2026-10-23, PowerProbe 3차): 측정 불가.** ANE 요청을 초당 4회부터 최대 속도까지 바꿔도 ANE0 전원 상태의 ACT 비율은 모두 100%였다. ANE 메모리 트래픽만 일한 양에 비례했다. `powermetrics`의 기본 출력, `--show-all`, `--show-extra-power-info`에도 ANE 활성 비율은 없었다. 결과를 사용자와 검토해 ANE 칸은 사용 중 여부와 전력 W를 보여주고 %는 측정 불가로 표시하기로 했다(1장). 같은 진단에서 CPU 번호와 E/P 묶음의 대응을 IODeviceTree `cluster-type`으로 확인했다.

이번 검토에서 추가로 확인한 내용: 로컬 `powermetrics` 바이너리의 ANE SW active/idle residency 출력 문자열, Stats의 온도·팬 읽기 및 SMC 제어 구현. 문자열·참고 구현은 현재 기기의 측정 결과가 아니다. ANE 부하 실행, 센서 실측, 팬 모드 변경, 보조 도구 설치는 아직 수행하지 않았다. → ANE 부하 실행은 2026-10-22 `Diagnostics/PowerProbe`에서 수행했다.

개인용 앱도 위젯 확장과 공유 컨테이너의 서명·권한 조건을 확인해야 한다. 현재 Apple 개발자 계정이나 인증서 상태는 확인하지 않았다. 유료 계정이 필수라거나 임시 서명만으로 모두 가능하다고 미리 단정하지 않는다. 실제 제약이 나타나면 필요한 설정과 대안을 구체적으로 정리한다.

## 8. 함께 진행할 구현 순서

1. **현재 단계: 구현 전 최종 설계 검토** — 확장형 위젯, E/P 사용률, CPU/GPU/ANE 전력, ANE %, 온도·팬 읽기, 마지막 선택 단계인 팬 제어를 구분한다.
2. **기술 검증** — 확장형 위젯의 실제 호스팅·높이 변경, ANE % 정의·출력, 전력 및 온도·팬 읽기와 권한 확인. 필수 항목이 막히면 결과를 검토하고 기술 선택 또는 범위를 합의한다.
3. **화면 시안 갱신 및 UI 구현** — 검증 결과를 반영하여 ANE %와 온도·팬을 추가하고, 알림 센터 확장형 위젯과 독립 실시간 패널의 접기/펼치기·상태·최근 그래프를 구현한다.
4. **네트워크 기록** — 오늘/세션 누적, 저장·복구, 인터페이스 변경 및 절전 처리.
5. **통합** — 공통 수집 데이터, E/P 사용률, CPU/GPU/ANE 전력, ANE %, 온도·팬, 배터리 충·방전 정보, 측정 시각, 표시/숨김 수집 정책 연결.
6. **실사용 점검** — 충전/방전/보류, 로그인, 절전·복귀, 날짜 변경, 여러 모니터, 리소스 사용량.
7. **마지막 선택 단계: 팬 제어** — 기본 모니터가 안정화된 후 제어·읽기 확인·자동 복귀를 검증한다. 미지원이어도 기본 모니터링을 중단하거나 미완성으로 취급하지 않는다.

수집 실패·카운터 초기화·날짜 변경·절전·재실행처럼 잘못된 수치가 생기기 쉬운 경계를 검증한다. 첫 기술 검증의 통과 기준은 확장형 위젯의 실제 동작, E/P 사용률·CPU/GPU/ANE 전력·ANE %의 유효한 수집 및 의미 확인, 대표 온도·팬 RPM 읽기다. 일부 값이 보이는 것만으로 모든 필수 요구가 충족됐다고 처리하지 않는다. 기본 앱은 이 결과를 바탕으로 통합하고, 팬 제어에는 독립적인 통과 기준을 둔다.

## 9. 선택 기능: 실시간 패널의 팬 RPM 조절

- 기본 모드는 **시스템 자동**이다. 첫 제어 범위는 팬별 **수동 목표 RPM 설정 / 자동으로 복귀**로 제한하는 안을 제안한다. 온도 곡선, 강제 팬 정지, 부팅·앱 재실행 시 수동 설정 자동 적용은 초기 범위에서 제외한다.
- 팬 상세에 실제 RPM, 요청한 목표, 읽어 확인한 모드를 표시한다. 지원하지 않는 팬은 제어부를 활성화하지 않는다. 확인된 팬별 허용 범위만 수락하며, 하한·상한 값의 존재만으로 모든 조건에서 안전하다고 판단하지 않는다.
- 명령 전송 성공만으로 적용 성공을 표시하지 않는다. 모드·목표 읽기 확인과 실제 RPM 변화를 따로 확인하고, OS가 제어를 회수하면 그 상태를 반영한다. OS와 반복적으로 제어권을 다투는 재시도나 검증되지 않은 thermal 보호 해제는 도입하지 않는다.
- 권한이 필요한 경우 인증된 앱의 제한된 팬 명령만 받는 보조 서비스를 사용한다. 임의 SMC 키 쓰기나 임의 명령 실행 인터페이스를 노출하지 않는다. 앱 전체를 관리자 권한으로 실행하지 않는다.
- 수동 제어 중에는 패널이 닫혀도 온도·팬 읽기 및 연결 감시를 유지한다. 활성 상태는 메뉴 막대에서도 알 수 있게 하고, 종료·절전·센서 오류·연결 소실 또는 시스템의 심각한 열 상태에서는 자동 복귀를 요청하고 결과를 확인한다.
- 앱 연결의 유효 시간과 보조 서비스 감시를 둬 앱 비정상 종료 시 복귀를 시도한다. 복귀 실패는 성공처럼 숨기지 않는다. 보조 서비스 자체의 고장까지 자동 복귀가 보장된다고 가정하지 않으며, 정상 종료·강제 종료·절전/복귀·통신 실패의 실제 동작을 제어 기능 활성화 전에 검증한다.
- 재시작 시에는 실제 모드를 다시 조회하며, 저장된 수동 RPM을 자동으로 재적용하지 않는다. 다른 팬 제어 앱과의 동시 제어도 검증 항목이다.
- 알림 센터는 RPM·온도·모드 조회만 수행한다. 팬 제어의 장애가 기본 수집과 위젯을 중단시키지 않도록 분리한다.

## 10. 최종 검토 결과와 진행 기준

| 결정 항목 | 설계 판단 | 다음 확인 |
|---|---|---|
| 위젯 외곽 높이 확장 | 필수 UX 유지, 가장 큰 UI 기술 의존성 | **검증 완료: macOS 27.0.1 미지원**. 대안 합의: WidgetKit 위젯 안에서 요약 ↔ 상세 전환. 버튼 전환·App Group 공유·백그라운드 갱신(5초 요청을 그대로 반영) 확인(2026-10-22). 장시간 유지는 실사용 점검에서 확인 |
| ANE % + W | 필수 목표로 추가, 두 지표의 의미·상태 분리 | W: 관리자 권한으로 측정 확인, 보조 프로그램으로 수집 합의. %: 측정 불가 확인(2026-10-23). 사용 중 여부(권한 불필요)와 W를 보여주고 %는 `— · 측정 불가`로 표시하기로 합의 |
| CPU·ANE 전력 권한 | 관리자 권한 보조 프로그램으로 수집(2026-10-23 합의) | 개인 팀 서명으로 `SMAppService` 등록과 XPC 통신 진단 |
| E/P·GPU 사용률 정의 | E/P: OS CPU 시간 묶음별 평균, GPU: Device Utilization (2026-10-23 합의) | 코어와 E/P 묶음 대응을 IODeviceTree `cluster-type`으로 확인 완료(2026-10-23) |
| 온도·팬 RPM | 기본 모니터링에 추가 | 센서와 팬을 읽기 전용으로 탐색·실측 |
| 그래프 전달·갱신 | 공통 수집 + 제한된 이력 전달 | 위젯 표시 중 전달, 종료/오류 시 오래된 값 구분 |
| 팬 RPM 제어 | 마지막 선택 단계, 패널 전용 | 권한·적용 확인·자동 복귀·감시 실패 시험 |

전체 수집·저장 구조는 유지할 수 있다. 현재 단계는 **설계 반영 완료**이며 **기술 검증 완료**가 아니다. 다음 실제 작업은 본 UI 전체 구현에 앞서 확장형 위젯 진단과 센서 읽기 진단을 작게 만드는 것이다. ANE % 또는 위젯 확장을 확보하지 못하면 임의 대체하지 않고 결과를 사용자와 검토한다.
