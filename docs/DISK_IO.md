# 디스크 I/O 설계

작성: 2026-11-03 · 브랜치: `main` (`01d132e` 다음)

상태: **화면·범위 확정(2026-11-03).** 다음은 구현(아래 '구현 순서').

설계 문서(`PROJECT_DESIGN.md`)의 1장 범위(CPU·RAM·GPU·ANE·배터리·네트워크·온도·팬)를 넓히는 사용자 요청이다. 그 문서는 다른 쪽에서 관리하므로 디스크 설계는 이 문서에 따로 적는다. 2·3·4장의 원칙(지어낸 값 금지, 값마다 상태와 측정 시각, 중복 합산 금지, 수집 주기, 30분 그래프 기록, 30초 묶음 저장)은 그대로 따른다. 진단 결과는 `Diagnostics/DiskProbe/README.md`.

## 확정한 범위 (2026-11-03 사용자 결정)

- 필수: **읽기·쓰기 속도**와 **바쁜 정도**. 용량은 넣지 않는다.
- 대상은 **물리 디스크 전부, 디스크별로** 보여준다. 디스크 이미지(`Physical Interconnect` = `Virtual Interface`)는 뺀다 — 이미지의 I/O는 그 파일이 있는 실제 디스크에도 같이 세어진다(진단: 이미지에 쓴 50 MB가 disk0에도 53 MB).
- 바쁜 정도는 **평균 동시 요청 수**(A안)로 보여준다. 써 보면서 뺄지 보강할지 사용자가 정한다.
- **SMART를 지원하는 디스크만** 펼친 상세에 SMART 값을 보여준다.
- 항목 색은 새 색 **청록**을 더해 디스크 기본 색으로 쓴다. 두 번째 계열(쓰기)은 다른 항목처럼 같은 색을 연하게.
- 패널 위치는 **배터리와 네트워크 사이**. 순서를 저장해 둔 경우에도 배터리 바로 뒤에 끼운다.
- 위젯은 패널을 다 만든 뒤에 정한다.
- 화면은 **B안**(시안 '디스크 B안'): 펼친 상세 맨 위에서 디스크를 골라 한 디스크씩 본다.

## 값과 출처

모두 관리자 권한 없이 읽는다.

| 값 | 출처 · 계산 | 비고 |
|---|---|---|
| 읽기·쓰기 속도 | IORegistry `IOBlockStorageDriver` → `Statistics`의 `Bytes (Read/Write)` 증가량 ÷ 실제 경과 시간 | 실제로 읽고 쓴 양과 0.1% 안 |
| 평균 동시 요청 | (`Total Time (Read)` + `Total Time (Write)`)의 증가량(ns) ÷ 경과 시간(ns) | 동시 1·8·32개 부하에서 0.9·6.9·26.9. **활성 시간 %가 아니다**(100%를 넘는다). 100%에서 자르지 않는다 |
| 응답 시간 (읽기·쓰기) | `Total Time` 증가량 ÷ `Operations` 증가량 | 그 구간 작업이 적으면 '—'(아래) |
| 초당 작업 (읽기·쓰기) | `Operations` 증가량 ÷ 경과 시간 | |
| 오늘 누적 (읽기·쓰기) | `Bytes` 증가량을 날짜별로 더함 | 네트워크 오늘 누적과 같은 규칙(기준 날짜 표시, 잠자기·자정, 카운터 감소·재연결은 새 기준점) |
| 오류·재시도 | `Errors`·`Retries` (읽기·쓰기) | 0이면 줄을 보이지 않음 |
| SMART | `IONVMeSMARTInterface`의 `SMARTReadData`(NVMe SMART 로그 512바이트, 규격 위치대로 풂) | `NVMe SMART Capable`인 디스크만. 1분마다 |

- 쓰지 않는 것: `Latency Time (Read/Write)`(늘 0). '사용 중/쉬는 중'(가만히 있어도 거의 매초 작업이 있어 늘 사용 중).
- 응답 시간 '—' 기준: 구간 안 작업 수가 적으면(초기값: 그 방향 작업이 초당 10개 미만) 응답 시간을 보이지 않는다. 진단에서 작업이 1~3개뿐인 구간은 0.8~1.3 ms로 튀었다(쉬던 디스크가 깨어나는 시간으로 보임). 기준은 써 보면서 조정한다.
- 이름: 내장 SSD는 '내장 SSD', 내장 SD 카드 리더는 'SD 카드', 그 밖은 볼륨 이름 → 없으면 기기 이름(`Product Name`). 상세에는 기기 이름과 연결 위치(내장·외장)를 작게.

### SMART 항목

- 늘 보임: 수명 사용 %(`percentage_used`), 예비 공간 %(`available_spare`), 총 쓰기·총 읽기(`data_units` × 512,000 바이트), 사용 시간(`power_on_hours`), 전원 켠 횟수, 비정상 종료
- 문제 있을 때만 보임: 위험 경고(`critical_warning` 비트), 매체 오류, 오류 기록, 고온 시간. 예비 공간이 기준(`spare_threshold`) 아래면 그 값도 경고 색
- 넣지 않음: 컨트롤러 사용 시간(이 SSD는 늘 0), 명령 횟수, SMART 온도(온도·팬 카드의 SSD 온도와 겹침)
- 측정 시각을 SMART 제목 옆에 보인다(1분마다 읽어서 다른 값보다 늦게 바뀜). 읽지 못하면 '읽지 못함 · 다시 시도 중'
- 확인: 1 GiB를 쓰자 총 쓰기량이 1,086 MB 늘었다(나머지는 그동안의 시스템 쓰기)

## 화면 (시안 '디스크 B안', '디스크 값 상태')

- **접힌 카드**: 제목 '디스크', 디스크마다 한 줄 — 이름 · 읽기 · 쓰기 · 동시(평균 동시 요청). 위에 작은 열 이름 줄
- **펼친 상세**: 그래프 기간(1분·5분·30분) → 디스크 고르기(분절 단추, 디스크가 하나면 숨김) → 기기 이름·연결 위치 → 속도 그래프(읽기 진하게·쓰기 연하게, 범례에 지금 값) → 평균 동시 요청 그래프 → 값 표(응답 시간 · 초당 작업 · 오늘 누적, 열은 읽기·쓰기; 오류·재시도 줄은 있을 때만) → SMART(지원하는 디스크만)
- 고른 디스크는 앱 실행 동안 기억한다. 고른 디스크가 빠지면 첫 디스크로
- 그래프는 지금 패널과 같은 방식: 왼쪽 44pt 눈금 칸(위·가운데·바닥, 단위는 맨 위만), 가운데 점선, 아래 '1분 전 · 지금'. 속도 축은 자동(1·2·2.5·5 × 10ⁿ), 동시 요청 축도 자동
- 상태: 연결 직후·깨어난 직후 속도 '준비 중', 동시 '—'. 디스크가 빠지면 그 줄과 그래프 기록이 사라진다(네트워크 인터페이스와 같음). 한 디스크의 실패가 다른 디스크 표시를 막지 않는다
- 설명 문단은 넣지 않는다(문구 규칙)

## 수집

- 패널 열림 1초, 닫힘은 다른 시스템 값과 같이 약 10초(오늘 누적은 누적 카운터 차이라 간격이 길어도 빠지지 않음). 잠자기 때 중단
- 디스크 목록은 연결·분리 알림(`IOServiceAddMatchingNotification`) 또는 몇 초마다 다시 훑어 갱신. 디스크 하나 읽는 데 20~90 µs
- 그래프 계열: 디스크마다 읽기·쓰기 속도, 평균 동시 요청. 디스크는 IORegistry 항목 ID로 구분(같은 BSD 이름이 다른 디스크에 다시 쓰일 수 있음)
- 오늘 누적 저장: 디스크마다 고정 키(기기 이름 + 일련번호의 해시, 일련번호 자체는 저장하지 않음)로 최근 7일, 30초마다·잠들기 전·종료 때
- SMART: 플러그인은 디스크마다 한 번 만들어 두고(5~8 ms) 1분마다 읽음(0.4~1.4 ms)

## 구현 순서

1. **수집**: 디스크 목록(물리 디스크만)·통계 차이 계산(순수 값 타입으로 떼어 경우별 시험)·스냅샷·그래프 계열·수집 일정 연결. DEBUG 출력으로 활성 상태 보기와 비교
2. **오늘 누적**: 네트워크 규칙을 디스크에 맞게 재사용, 날짜별 저장
3. **SMART**: 읽기(앱 타깃에 작은 C 파일 + 브리징 헤더, 또는 Swift로 직접 — 1단계 때 정함)
4. **화면**: 항목 색 청록·`MonitorItem`·`PanelSection` 추가(저장된 순서에 배터리 뒤로 끼우기), 접힌 카드, 펼친 상세(B안), 값 상태
5. **마무리**: 외장 디스크 꽂고 빼기, 잠자기·깨어남, 자원 사용 측정, README 진행 상황
